# AGENTS.md

Инструкции для ИИ-агентов (Claude Code, Codex, Hermes и др.) в этом репозитории.

## Проект

Локальный TTS-сервер на Qwen3-TTS VoiceDesign (MLX, macOS arm64) для Hermes Agent. Публичный репозиторий на GitHub.

| Путь | Что это |
| --- | --- |
| `scripts/hermes_tts_server.py` | FastAPI-сервер, держит модель, `GET /health`, `POST /tts` |
| `scripts/hermes_tts_client.py` | Командный провайдер Hermes, только stdlib |
| `scripts/healthcheck.sh` | Проверка `/health` |
| `install.sh`, `uninstall.sh` | Установка и снятие LaunchAgent, POSIX `sh` |
| `config/tts.yaml` | Фрагмент `~/.hermes/config.yaml` |
| `tests/` | Короткие тесты без модели |

## Запреты

- Не коммитить и не пушить. Не переписывать историю git. Это делает владелец.
- Не запускать `install.sh` и `uninstall.sh` и не трогать `launchctl`: они меняют систему пользователя.
- Не скачивать модель и не запускать сервер без явной просьбы.
- Не читать и не править `~/.hermes/config.yaml`.
- Не добавлять секреты, личные пути и имена в файлы репозитория.

## Правила кода

- Python 3.11+ (минимум рантайма, его проверяет `install.sh`; должен совпадать с `requires-python` и `target-version` в `pyproject.toml`), стиль и правила — ruff из `pyproject.toml`. Не ослаблять правила ради прохождения.
- Клиент — только stdlib: он запускается из Hermes на каждый запрос.
- Сервер никогда не скачивает модель: `HF_HUB_OFFLINE=1` в процессе, проверка `hf cache verify` в подпроцессе (пропускается, если рядом с сервером есть файл `SKIP_MODEL_VERIFY`), загрузка только из кэша. Не возвращать автозагрузку.
- Сервер зависит от `mlx-audio` версии, зафиксированной в `install.sh`. Перед правкой вызовов модели сверяться с исходниками этой версии, не по памяти.
- Shell-скрипты — POSIX `sh`, без bash-конструкций.
- Тесты короткие, без модели и сети: заглушки вместо сервера.
- Рамки проекта: только `Qwen3-TTS-12Hz-1.7B-VoiceDesign` и только Hermes Agent. Не добавлять поддержку других моделей и клиентов и не чинить работу с ними.
- Не раздувать функционал: новые возможности сначала в `TODO.md`. Выполненный пункт удалять из `TODO.md`: история хранится в `CHANGELOG.md`.
- Известные баги — в `KNOWN_ISSUES.md`, по шаблону из шапки файла, с номером `BUG-N`. Номера не переиспользуются. Гипотезы помечать как непроверенные. Исправленный баг удалять оттуда и записывать в `CHANGELOG.md` → `[Новое]` → «Исправлено» с номером бага.

## CHANGELOG

- Формат — [Keep a Changelog 1.1.0](https://keepachangelog.com/ru/1.1.0/) в русском переводе, версии — SemVer.
- Изменение, заметное пользователю (поведение сервера и клиента, API `/tts`, переменные окружения, установка, конфиг Hermes), записывать в раздел `## [Новое]` в той же правке, что и само изменение. Запись идёт под типом из списка: Добавлено, Изменено, Устарело, Удалено, Исправлено, Безопасность. Пиши для человека: что изменилось и что ему сделать.
- Не записывать: CI, линтеры, тесты, рефакторинг без изменения поведения, обновления dev-зависимостей, правки `AGENTS.md`.
- Не поднимать версию, не ставить дату выпуска и не создавать теги. Выпуск делает владелец по README, раздел «Выпуск версии». Агент поднимает версию только по явной просьбе.
- Уже выпущенные разделы не переписывать: исправление выпущенного — новая запись в `[Новое]`.
